# 并发能力分析与优化建议

## 当前架构

### 配置
- **Worker数量**: 1个
- **Worker类型**: sync（同步）
- **后台处理**: Python threading
- **立即返回**: ✅ 视频生成请求立即返回

### 并发机制

```python
# 请求流程
1. 用户发起视频生成请求
2. API立即创建任务并返回videoId (< 1秒)
3. 后台线程异步处理视频生成 (3-5分钟)
4. 用户轮询查询状态
```

## 并发能力评估

### ✅ 可以并发的场景

| 场景 | 并发数 | 说明 |
|------|--------|------|
| 健康检查 | 50+ | 轻量请求，无阻塞 |
| 视频状态查询 | 50+ | 轻量请求，查询字典 |
| 视频生成请求 | 10-20 | 立即返回，后台处理 |
| 视频下载 | 10+ | 文件服务，IO密集 |

### ⚠️ 可能排队的场景

| 场景 | 并发数 | 说明 |
|------|--------|------|
| GPT优化 | 3-5 | 等待OpenAI响应，阻塞请求 |
| 上传大文件 | 5-10 | IO密集，可能阻塞 |

## 瓶颈分析

### 主要瓶颈：GPT优化请求

**问题**：单worker的同步处理会导致GPT请求排队

**影响**：
- 3个用户同时生成视频 → 第3个用户等待12秒才能开始
- 体验不佳

### 次要瓶颈：OpenAI API限制

**OpenAI限制**：
- Tier 1用户：3 RPM（每分钟3个请求）
- 超过限制会收到429错误

## 优化方案

### 方案1：增加Worker（推荐）

**适用场景**：10-100用户同时使用

```bash
# 修改为2-4个worker
ExecStart=.../gunicorn -w 2 -b 0.0.0.0:5000 --timeout 600 sora_api:app
```

**配合Redis共享状态**：

```python
import redis
redis_client = redis.Redis(host='localhost', port=6379, db=0)

# 存储任务状态
redis_client.hset(f'video:{video_id}', mapping={
    'status': 'queued',
    'progress': 0
})
```

### 方案2：使用异步Worker（高性能）

**适用场景**：100+用户同时使用

```bash
# 使用gevent worker
pip install gevent
gunicorn -w 4 -k gevent -b 0.0.0.0:5000 --timeout 600 sora_api:app
```

**优势**：
- 单worker可处理1000+并发连接
- 异步IO，不阻塞

### 方案3：任务队列（企业级）

**适用场景**：1000+用户，高可用

```bash
# 使用Celery处理耗时任务
pip install celery redis

# 架构
API服务器 → Redis队列 → Celery Worker → 视频生成
```

## 当前配置建议

### 对于小程序（预期<50用户）

**保持单worker** + **优化GPT调用**：

```python
# 添加超时保护
@app.route('/api/optimize-prompt', methods=['POST'])
def optimize_prompt():
    try:
        # 设置更短的超时
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[...],
            timeout=15,  # 15秒超时
        )
    except Timeout:
        # 返回默认优化结果
        return jsonify({
            'success': True,
            'optimizedPrompt': user_description  # 不优化，直接使用原文

**升级为2-4 worker** + **Redis状态共享**

```

## 监控指标

@app.route('/api/metrics')
def metrics():
    return jsonify({

### 报警阈值

- 并发任务数 > 10 → 考虑增加worker
- 响应时间 > 5秒 → 检查瓶颈
- 内存使用 > 1GB → 可能内存泄漏

## 结论

### 当前配置（单worker）

**适用范围**：
- ✅ 1-50个并发用户
- ✅ 小程序、MVP、测试环境
- ✅ OpenAI API限制下（3 RPM）

**不适用**：
- ❌ 100+并发用户
- ❌ 生产环境、商业应用
- ❌ 需要高可用性

### 推荐配置

| 用户量 | Worker | 状态存储 | 说明 |
|--------|--------|----------|------|
| <50 | 1 | 内存 | 当前配置 ✅ |
| 50-200 | 2-4 | Redis | 推荐升级 |
| 200-1000 | 4-8 | Redis | 生产环境 |
| >1000 | 8+ + 负载均衡 | Redis + 队列 | 企业级 |
